# Study & Reference Notes: Enterprise Agentic AI (ADK, MCP, & A2A) on GCP

This reference note consolidates key architectural patterns, code designs, and deployment models for running **Google Antigravity SDK (ADK)**, **Model Context Protocol (MCP)**, and **Agent-to-Agent (A2A)** workflows on Google Cloud Platform (GCP).

---

## 1. Google Antigravity SDK (ADK) Core

The Google Antigravity SDK is a stateful, agent-centric Python framework designed to build autonomous workloads around Google's Gemini models (such as `gemini-3.5-flash` and `gemini-3.5-pro`).

### Three Pillars Architecture
```
┌────────────────────────────────────────────────────────┐
│                        Agent                           │
│  (Configures Personas, System Instructions, & Tools)   │
└──────────────────────────┬─────────────────────────────┘
                           │ Instantiates
                           ▼
┌────────────────────────────────────────────────────────┐
│                    Conversation                        │
│  (Manages State, History, Context Compaction, & turns) │
└──────────────────────────┬─────────────────────────────┘
                           │ Communicates via
                           ▼
┌────────────────────────────────────────────────────────┐
│                     Connection                         │
│  (Handles gRPC/HTTP Transport layer to backend LLM)    │
└────────────────────────────────────────────────────────┘
```

1.  **Agent**: The configuration and orchestration entry point. It registers:
    *   Personas and system instructions (`system_instructions`).
    *   Capabilities configs (e.g., subagents, code execution).
    *   Local custom tools and remote MCP server endpoints.
2.  **Conversation**: Represents the active session state. It handles:
    *   History accumulation and context windows.
    *   Compaction algorithms to prune or summarize history when near limit.
    *   Streaming responses and reasoning thoughts.
3.  **Connection**: Manages lower-level transports (SSE, HTTP, gRPC) to remote model backends (Vertex AI / Gemini APIs), abstracting network details from the code.

### Critical ADK Config Features
*   **Custom Python Tools**: Generated by attaching a docstring to a Python function. The SDK parses parameters and docstrings to create schema definitions for tool-calling:
    ```python
    def lookup_instance_status(zone: str) -> str:
        """Checks GCP compute instances in the given zone.
        Args:
            zone: The target zone (e.g. us-central1-a)
        """
        return "status: RUNNING"
    ```
*   **Structured Outputs**: Enforces model outputs to match Pydantic schemas using the `response_schema` parameter:
    ```python
    class EstimateReport(BaseModel):
        total_cost: float
        recommendation: str
        
    config = LocalAgentConfig(response_schema=EstimateReport)
    ```
*   **Thoughts Streaming**: Allows exposing Gemini's reasoning process (thinking tokens) before outputting the final user-facing text.

## 2. Model Context Protocol (MCP)

Model Context Protocol (MCP) is an open-source standard enabling applications to securely expose custom data and tools to LLMs. It decouples tool execution services from core agent brains.

### Transport Modes
| Transport Type | Use Case | Lifecycle Management |
| :--- | :--- | :--- |
| **Stdio** | Local development and testing | Managed by the ADK agent process (spawns and terminates the MCP process as a local subprocess). |
| **SSE (Server-Sent Events)** | Enterprise production deployment | Managed externally (hosted as a web service, e.g. on Cloud Run, and connected via HTTP over HTTPS). |

### MCP Tool Security & Permissions
By default, the SDK allows execution of all MCP tools (except direct system shell execution, which prompts a safety warning).
If using a **strict safety boundary** (e.g., deny-all policy), tools must be explicitly whitelisted by name:
```python
from google.antigravity import policy

# Deny everything by default, then selectively allow specific tools
config = LocalAgentConfig(
    policies=[
        policy.deny_all(),
        policy.allow("fetch_jira_ticket"),
        policy.allow("send_slack_alert")
    ]
)
```

## 3. Agent-to-Agent (A2A) Orchestration

Complex workflows require dividing a task into specialized steps and executing them across different agents rather than overloading a single model context.

### Supervisor-Worker Pattern
*   **Supervisor Agent**: Receives raw prompts, determines required domains, calls subagents, monitors execution states, and aggregates subagent findings into a final report.
*   **Worker Agents**: Subagents configured with narrow system instructions (e.g., a "Security Auditor" or "Terraform Builder") and equipped only with tools relevant to their scope.

### Enablement in ADK
A2A is enabled using `CapabilitiesConfig` inside `LocalAgentConfig`:
```python
from google.antigravity import LocalAgentConfig, types

config = LocalAgentConfig(
    capabilities=types.CapabilitiesConfig(
        enable_subagents=True  # Instructs the Supervisor it can spawn child agents
    )
)
```

### Production Scale: Pub/Sub Task Delegation
For real-time enterprise workloads, synchronous model orchestration faces timeout limits. The recommended GCP pattern uses an **asynchronous queue**:
1.  **Supervisor** publishes a task JSON to a **Cloud Pub/Sub** topic.
2.  **Worker Agents** running in individual GKE containers pull the task from the queue, instantiate their ADK Agent, execute work, and publish the response to a result topic.
3.  This decouples compute resources and allows individual steps to scale independently.

## 4. GCP Architecture & Security Mapping

Deploying these agent patterns securely on Google Cloud requires strict boundary setups:

```
                  ┌───────────────────────────────────────────────┐
                  │          VPC Service Controls (VPC-SC)        │
                  │                                               │
                  │   ┌───────────────┐       ┌───────────────┐   │
                  │   │  Shared VPC   │       │   Cloud Run   │   │
                  │   │  (GKE Nodes)  │◄─────►│ (MCP Servers) │   │
                  │   └──────┬────────┘       └───────────────┘   │
                  │          │                                    │
                  │          ▼                                    │
                  │   ┌───────────────┐                           │
                  │   │   Vertex AI   │                           │
                  │   │ (Gemini API)  │                           │
                  │   └───────────────┘                           │
                  └───────────────────────────────────────────────┘
```

*   **VPC Service Controls (VPC-SC)**: Establishes a perimeter around API services (Vertex AI, Cloud SQL, Secret Manager). This prevents worker nodes from sending data to external, unapproved API endpoints.
*   **Workload Identity**: Links Kubernetes Service Accounts (KSA) inside GKE with Google Service Accounts (GSA) to fetch temporary Google OAuth tokens dynamically. Avoids baking static service account JSON keys into container builds.
*   **Secret Manager**: Acts as a central database for MCP integration credentials. API keys are injected directly into environment variables or mounted as files at runtime, avoiding code leakage.
*   **Observability & FinOps**: 
    *   **Thinking Tokens**: Reasoning models generate internal thinking tokens. It is vital to track and parse both input, output, and thinking tokens to monitor model cost trends.
    *   **Log Sinks**: Route agent traces and billing logs from GKE/Cloud Run directly to BigQuery to audit agent behaviors and compute token-cost metrics.
